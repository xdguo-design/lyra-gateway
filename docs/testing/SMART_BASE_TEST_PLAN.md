# 智能底座测试计划

**版本**：v1.0 · **日期**：2026-09-29 · **关联需求**：[智能底座 PRD](../product/SMART_BASE_PRD.md)
**范围**：标明当前可测能力和 P0/P1/P2 目标验收；规划中能力不视为已经实现。

## 1. 测试目标

确认研发可以用统一 API 调用多个 Provider；遇到允许切换的故障时由备用线路恢复请求；每次调用均可核对状态、最终线路和可获得的 Usage/耗时；密钥不会通过界面、接口或日志泄漏。同步验证配额、成本治理和 Agent/知识工作流的后续验收边界。

## 2. 范围与状态标记

- **P0**：首期发布门槛，所有 P0 用例通过后才可宣布核心闭环完成。
- **P1**：租户、调用方 Key、配额成本和高级路由阶段验收。
- **P2**：Agent、Tools、Skills、Workflow、Knowledge、Memory 与评测阶段验收。
- **已有**：仓库目前有对应实现或测试入口；仍需按本计划补齐端到端证据。
- **部分**：只覆盖子集，不能据此宣称完整需求已经满足。
- **规划**：功能未交付；验收用例暂作需求占位。

## 4. P0 端到端验收流程

### 前置条件

1. 使用测试环境和两个可控 Mock Provider；CI 不使用真实 Provider Key。
2. 配置两个支持同一能力的测试模型，首选线路优先级更高。
3. 开启调用记录，并为测试请求设置可检索的请求关联标识（若客户端支持）。

### 执行步骤

1. 通过管理台添加 Provider，输入测试凭据并验证连接。
2. 发现或登记一个模型，检查能力、健康状态和优先级后启用。
3. 使用统一 API 成功请求模型 A；核对结果和调用记录。
4. 将首选 Mock Provider 配置为超时或返回可切换的速率限制错误，再提交等价请求。
5. 检查备用 Provider 返回成功；从请求列表打开该请求详情视图，核对主线路与备用线路的尝试顺序、耗时、脱敏错误类别和最终成功线路，确认不包含上游原始响应正文或密钥。
6. 令两个 Provider 都失败；检查重试次数有界、最终错误可诊断，调用记录仍可检索。
7. 对已保存凭据执行管理页面检查、接口响应扫描和日志扫描，确认无明文密钥。
8. 验证错误类别不适用 Fallback 时只发生预期次数的上游请求。

### 通过标准

- 所有步骤结果与预期一致，且无未解释的额外 Provider 请求。
- Fallback 不改变客户端使用的统一 API 契约。
- 状态、线路和 Usage 信息能从调用记录中交叉核对。
- 密钥扫描零泄漏；失败原因不暴露内部堆栈。
- 任一核心项失败时，P0 不通过；记录请求关联标识、模拟响应、日志和复现步骤。

## 5. 测试类型与责任

| 测试类型 | 验证内容 | 建议执行时机 |
|---|---|---|
| 单元测试 | 路由候选筛选、错误分类、重试上限、脱敏、配额和 Usage 计算 | 每次提交 |
| API 集成测试 | 管理接口、统一模型 API、认证、Provider 替身和记录落库 | 每次提交/合并前 |
| 前端测试 | Provider 配置、模型筛选、状态/空态、表格过滤、国际化 | 每次提交 |
| 端到端测试 | P0 闭环、失败切换、Usage/日志和密钥检查 | 发布候选版本 |
| 安全测试 | 凭据响应/日志扫描、越权读取、注入与工具权限（P2） | 发布前及安全变更后 |
| 兼容性测试 | OpenAI 兼容客户端、受支持协议和模型能力矩阵 | 发布候选版本 |
| 人工验收 | 自托管安装、管理台配置、故障提示和运维操作 | 每个阶段发布前 |

## 7. 环境与数据要求

- Provider 响应由确定性 Mock 控制：成功、超时、限流、鉴权错误、服务端错误和无效响应。
- 测试密钥使用专门的无权限占位值；禁止在仓库、CI 输出或截图中放真实密钥。
- 测试记录应使用虚构请求内容和非敏感数据；截图中的演示统计需标注“演示数据”。
- 对会改变上游状态的调用（如图像生成、工具写入）使用替身或沙箱，并验证不会被自动重放。
- 对成本、质量和延迟的策略测试固定模型、固定输入与可控 Provider 状态，不将演示分数解释为生产基准。

## 8. 缺陷分级与报告

- **P0 阻断**：统一调用不可用；Fallback 导致错误路由/无限重试/重复副作用；密钥泄漏；跨租户数据暴露。
- **P1 高**：Usage/线路记录缺失或误导；配额可绕过；路由策略明显违反配置；关键运维状态不可见。
- **P2 一般**：不影响闭环的界面、文案、筛选或非核心体验问题。

每条缺陷记录：版本/提交、环境、测试 ID、前置条件、复现步骤、预期和实际结果、脱敏后的请求/响应与日志、关联请求 ID。

## 9. 当前限制

本计划定义的是验收方法，不表示所有阶段功能已存在。Agent/Tools/Skills/Workflow/Knowledge/Memory、完整调用方 Key、多租户隔离、成本中心、告警和高级路由在 PRD 中属于规划或部分能力；在对应功能交付前，SB-P1/SB-P2 用例不能标为通过。
