# FreeLLM Gateway 管理台信息架构与界面设计

## 1. 目标

重新规划管理台页面元素、信息优先级和操作路径，让用户能快速判断网关状态、定位异常，并完成模型接入与路由管理。此次是前端信息架构和视觉呈现调整，保留现有业务能力、API、数据模型和六个一级页面入口。

## 2. 当前问题

- 模型池把模型表、Provider 卡片、模型和 Provider 表单、多连接批量接入、请求日志连续放在一页，管理任务混在一起，主要内容被长表单和日志推远。
- 页面标题重复，模型状态、配置入口和主要操作的层级不够清楚。
- 概览同时展示接口信息、路由说明、统计和日志，缺少首先回答“服务是否正常、哪里异常”的优先级。
- 目录卡片的“加入模型池”之后跳转到模型页，缺少清楚的进度和结果反馈。
- 当前浅蓝背景、山形侧栏插画和手写标语占用视觉注意力，但对运维判断没有帮助。

## 3. 设计原则

1. **先看状态，再做操作**：每个页面首屏先呈现该任务最关键的状态、筛选或主要操作。
2. **一个工作区聚焦一种任务**：模型管理、连接接入、批量导入和日志分区呈现。
3. **摘要优先，详情按需展开**：表格显示决策所需字段；编辑字段、诊断信息和次要配置通过行详情、侧面板或二级区域查看。
4. **操作结果可见**：提交、探测、导入、目录同步等操作都展示进行中、成功或失败状态，并保留可理解的错误原因。
5. **减少装饰，建立一致层级**：使用明亮中性色作为底色、深石墨文字、单一蓝色强调操作；状态色只表示健康、警告和错误。移除与任务无关的插画和标语。

## 4. 全局框架

- 保留现有“概览、模型池、Token 用量、请求路由、目录同步、设置”六个一级导航入口。
- 侧栏展示产品标识、一级导航、网关在线状态和版本；移除山形装饰及手写标语。
- 页面顶部统一展示页面标题、简短用途说明和该页主操作。全局搜索、语言切换和 Admin Token 入口沿用现有能力，并保持在统一的顶部区域。
- 页面使用一致的标题、筛选栏、数据表、状态标签、表单分组、空状态和通知样式。
- 桌面端优先使用信息密度适中的表格和双栏工作区；窄屏改为单列，表格允许横向滚动，关键操作保持可见。

## 5. 页面与工作区

### 5.1 概览

首屏顺序：网关在线状态和刷新入口 → 核心指标 → 异常模型/连接 → 最近请求。核心指标优先包括启用模型、健康模型和异常连接；请求成功/失败通过最近请求列表直接呈现，不新增或自行计算成功率。所有数字仅使用现有接口返回字段。API 地址、令牌和文档链接收在单独的“客户端接入”区块，保留复制能力但不抢占运维状态的视觉优先级。

### 5.2 模型池

模型池拆分为四个同页工作区，以模型池页面内的横向标签切换，不增加一级侧栏入口或新后端资源；默认打开“模型列表”。切换工作区不离开 `#/models` 页面：

1. **模型列表**：顶部显示模型总数、健康数和异常数；主操作为添加模型。筛选栏放 Provider、运行状态和能力。表格优先展示模型、Provider、能力、价格、健康状态、优先级和常用操作。单行详情/编辑承载不常驻的完整配置。
2. **Provider 连接**：显示连接名称、协议、Base URL、关联模型数、最近探测状态；提供新增、编辑、发现模型、探测和删除入口。仍有关联模型时保留删除保护和原因提示。
3. **批量接入**：按“填写连接信息 → 验证并发现模型 → 选择模型 → 保存”的顺序呈现。多个 Provider 可分别显示验证结果；一条连接失败不能遮蔽其他连接的结果。
4. **请求日志**：提供模型、Provider、请求结果和时间范围筛选。表格展示请求 ID、路由结果、租户/应用、延迟和 Token；默认限制初始展示数量，并提供继续加载或分页的容器。

新增模型和编辑模型使用相同的分组表单，优先展示 Provider、模型名、凭据和能力；价格、公开注册/文档 URL、目录状态及说明作为次级配置。凭据保持密码掩码，不在页面回显。

### 5.3 目录同步

顶部集中放目录刷新、导出和同步操作，并明确显示最后一次操作结果。筛选项按搜索、来源/地区、Provider、能力和模型池状态组织。模型卡片优先展示名称、Provider、模型标识、能力、免费额度/限制说明和接入状态；注册及文档链接作为辅助操作。

点击“加入模型池”后，使用可见反馈说明模型已预填到模型配置，并提供“继续配置”入口；如果缺少 Endpoint、凭据或必填信息，显示缺项并引导补齐，不将跳转误报为已接入成功。

### 5.4 Token 用量

页面顺序为时间范围和租户/应用/Provider/模型筛选 → Token 与成本摘要 → 用量分组表 → 配额配置。配额编辑从摘要/对应分组进入，保存后显示确认结果。保留当前已有用量、成本、过滤和配额能力。

### 5.5 请求路由

先显示简短的路由流程概览，再按能力列出可用候选模型及优先级、Provider 和健康状态。禁用、异常或不满足能力要求的模型需要有明确状态说明；不在视觉层虚构新的路由策略或配置能力。

### 5.6 设置

将现有内容分为“租户与应用”“运行时接入信息”“服务路径与诊断信息”几个区块。创建租户、创建应用的表单与已创建列表相邻；应用密钥的一次性展示及复制反馈在创建后突出显示。运行时路径采用可复制的键值列表。

## 6. 交互和状态

- 列表加载、空结果、请求失败分别使用明确的加载、空状态和错误提示，并提供适用的重试入口。
- 破坏性操作继续使用确认或禁用保护；保存、探测和同步按钮在请求期间禁用重复提交并显示进行中状态。
- 成功消息说明实际结果；失败消息保留服务端返回的可操作原因，不只显示通用“失败”。
- 导航到模型池时默认进入模型列表；目录传入的预填模型数据在继续配置后打开模型表单并保留。刷新页面后不应把未完成表单伪装成已保存配置。
- 现有中英文文案能力继续生效；新增可见标签必须进入现有 i18n 字典。

## 7. 数据与边界

- 复用现有 React 页面、API 客户端和服务端端点；本次不改 API 协议、网关路由逻辑、鉴权方式、数据库结构或模型探针规则。
- 工作区拆分是前端呈现组织，不代表新增后端资源。除为列表分页复用已有查询参数外，不引入新的数据采集或统计定义。
- 任何在当前页面能完成的功能，改版后仍需有明确入口；如当前能力不存在，不在改版中新增业务承诺。

## 8. 验收标准

- 六个一级页面均使用统一的页面标题、主操作、状态、表单和空/错误状态层级。
- 模型列表首屏可找到模型状态和添加入口；Provider、批量接入、日志无需滚过长页面即可进入。
- Provider 验证、批量模型选择、模型新增/编辑、探测、启停、删除保护和日志筛选等现有能力仍可操作。
- 目录“加入模型池”操作明确呈现“预填/继续配置”结果；只有实际保存且验证后的模型才显示为已接入/健康。
- Token 用量筛选/配额、路由能力候选、设置中的租户/应用创建和复制能力均保留。
- 失败、加载和空结果具有可辨识提示；中英文下布局不溢出；桌面与窄屏均可完成核心流程。
- 实施后进行逐页浏览检查，并检查模型接入与目录加入这两条主要路径的成功和失败反馈。

## 9. 不在本次范围

- 不更换 UI 框架或增加大型组件库。
- 不调整后端 API、模型目录来源、探针行为、模型排序/路由策略及计费计算。
- 不重写业务文案或删除现有功能；视觉装饰可移除，但运行信息和客户端配置仍须可访问。
