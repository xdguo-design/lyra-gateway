# Lyra Gateway 产品需求文档：独立模型网关与共享 AI 底座

- 版本：评审稿 v1.0
- 日期：2026-10-02
- 产品：Lyra Gateway（当前实现名称 FreeLLM Gateway）
- 范围：独立模型接入，以及面向 Hub、Agents、Narrative、Print 的可组合接口

## 1. 问题与定位

多个 AI 应用若各自保存 Provider 密钥、实现模型路由和重试，将难以统一权限、额度、成本与故障处理。Gateway 作为模型访问的权威系统，统一管理 Provider、模型目录、能力标签、路由、配额、用量和密钥；业务应用仍拥有自己的任务、提示内容和结果。

Gateway 必须能独立运行：管理员可使用其管理界面，外部客户端可使用公开模型接口。加入 Lyra 组合后，Hub 负责展示连接与模型状态，Agents 负责 Agent 治理，Narrative 负责创作，Print 负责打印；这些系统不接管 Gateway 的 Provider 密钥或路由策略。

## 2. 当前能力与演进目标

| 范围 | 当前已具备 | 后续要求 |
| --- | --- | --- |
| 模型网关 | 多 Provider、模型路由、`auto` 选择、健康状态与失败切换 | 在应用与能力维度提供可解释的策略和可观测结果 |
| 对外调用 | OpenAI 兼容的模型目录、对话及图像生成接口；API Token 与管理 Token 分离 | 明确调用者身份、权限、额度、错误语义和契约版本 |
| 管理与密钥 | 独立管理界面；Provider 密钥按部署方式保护 | Hub 只保存访问 Gateway 所需的客户端凭据，不持有 Provider 密钥 |
| 部署 | 本地／桌面及单实例云部署 | 多实例前解决共享存储、配额预留和一致性问题 |

现有具体行为以仓库 API、README 与设计文档为准；本 PRD 将尚未实现的跨项目能力列为验收目标，不将其写成已交付事实。

## 3. 用户与使用方式

- **Gateway 管理员**：配置 Provider、模型及路由，查看健康、用量和故障。
- **应用开发者**：取得获授权的模型目录，调用适合业务任务的模型。
- **运维／财务人员**：按调用方追查请求、失败、额度与成本，不接触提示正文或 Provider 密钥。
- **业务用户**：在 Narrative、Print 或其他应用中使用 AI 功能，不必了解底层 Provider。

**独立模式**：Gateway 管理界面和模型 API 可直接使用；Hub 或 Agents 离线不影响已配置的 Gateway 服务。

**组合模式**：Hub 读取状态和模型目录，并仅在用户显式操作时发起生成检查；Agents 使用 Gateway 的应用级凭据执行模型步骤；Narrative 可将 Gateway 作为独立 Provider；Print 的 AI 模板辅助功能可选用 Gateway。每个消费方使用清楚的身份、权限与额度归属。是否通过 Hub 中转由应用集成契约确定，不能在一次请求失败后静默改走另一计费路径。

## 4. 用户故事与优先级

### P0：模型发现和稳定调用

作为应用开发者，我希望查询公开模型及能力信息，再发起模型请求，以便无需了解 Provider 内部地址和密钥。

- 目录只暴露允许调用的模型与必要元数据；空目录、未授权、服务未就绪分别可识别。
- 调用成功返回模型响应及关联 ID；失败能区分输入不支持、认证、额度、限流、超时和上游错误。
- `auto` 根据请求能力、已启用状态、健康和优先级选择路由；指定模型不得悄悄改用其他模型。
- 流式响应已输出内容后，不自动切换模型或重放请求；调用方能识别部分结果与失败。

作为平台管理员，我希望独立管理 Provider 和模型，同时让 Hub 只读取必要状态，以便保持职责和凭据边界。

- 管理与模型调用使用不同权限；Provider 密钥不出现在目录、调用结果、日志或 Hub 页面。
- `/health` 的进程存活与就绪、模型目录可访问性、可用模型数量分开呈现。
- Hub 关闭时，独立管理和已授权的模型调用仍可使用。

### P1：多应用治理

作为平台运营者，我希望区分 Hub、Agents、Narrative 和 Print 的调用身份、额度与用量，以便诊断成本和限制高风险调用。

- 每项调用能归属到应用身份及请求关联链路，且不会把用户敏感正文写入常规审计。
- 各应用凭据可独立撤销和轮换；管理凭据不充当业务调用凭据。
- 配额耗尽或限流时返回明确状态和可用的重试提示；失败计费与重试口径一致。

### P2：部署扩容

在共享状态与配额一致性方案通过评审后，再考虑多实例运行、跨区域部署和运行时替换。当前单实例云部署是明确约束，不以接口可扩展性推断已经具备水平扩容能力。

## 5. 组合使用流程

1. 管理员在 Gateway 内配置 Provider、模型与路由；Gateway 保存 Provider 凭据。
2. Hub、Agents、Narrative 或 Print 以各自获授权身份读取模型目录；Gateway 只返回可见模型。
3. 调用方提交模型请求并附关联 ID；Gateway 校验身份、能力、路由与额度。
4. Gateway 选择上游并返回结果、错误或流式状态；用量和成本归 Gateway 记录。
5. 业务应用解释结果并决定是否写入本领域数据。Narrative 的稿件批准、Print 的正式打印等高影响操作不得由 Gateway 直接完成。

Gateway 不可用时，各应用仍应保留非 AI 核心功能；依赖模型的功能明确报告不可用。Hub 不得仅凭 Gateway 进程健康就宣称模型生成可用。

## 6. 接口健壮性与扩展性要求

- **契约兼容**：公开接口遵循已声明的 OpenAI 兼容范围；扩展字段和能力元数据应保持旧客户端可解析。破坏性变更需要版本、迁移期及明确弃用说明。
- **错误与限流**：使用稳定错误码及合适 HTTP 状态，区分客户端错误、鉴权、权限、限流、配额、暂不可用与上游失败；给出关联 ID 和可用的重试时机，不回显内部密钥或完整上游错误。
- **超时与重试**：只在不产生重复费用或可确认未被上游处理时自动切换或重试；响应丢失、流式中断、上游部分成功必须可追查，不能伪装成新请求成功。
- **路由可解释**：能够说明模型被选中、跳过、熔断、恢复或因能力不符被拒的原因；配置变更保留审计线索。
- **安全隔离**：Provider 密钥仅存于 Gateway；客户端凭据按最小权限发放；浏览器与 Hub 上下文不持有 Provider 密钥。管理地址和业务接口分别保护。
- **观测与容量**：输出进程存活、存储就绪、路由健康、请求延迟、错误分类和用量。容量、SLA 与成本目标需在真实负载确定后量化；单实例限制在此之前保持显性。

## 7. 验收场景

- 不启动 Hub、Agents、Narrative 或 Print，Gateway 仍可独立管理模型并接受已授权客户端调用。
- Hub 可读取模型目录，区别空目录、错误凭据、Gateway 不可达和可调用模型；生成检查只能由用户显式触发。
- Agents 和 Narrative 能分别以自己的客户端配置访问 Gateway；其中一个服务停用或撤销凭据不影响另一个。
- Print 不配置 Gateway 时，模板、预览和正式打印仍正常；配置后仅 AI 辅助能力依赖 Gateway。
- Provider 返回 429、5xx、认证失败、超时或配额耗尽时，Gateway 给出可识别状态；流式已输出后不重复生成。
- API、日志、目录导出及 Hub 页面均不泄露 Provider 密钥。

## 8. 非目标与待决策

Gateway 不管理 Agent 定义、小说稿件或打印任务；不代替 Hub 的应用注册，也不自动绕过 Provider 的额度与限制。

待决策：每应用凭据与租户策略的具体发布范围、生产用量保留期限、目标 QPS／延迟／可用性、共享配额存储与多实例一致性方案、流式失败的用户提示规范。完成这些决策前，不承诺多租户或多实例生产能力。
